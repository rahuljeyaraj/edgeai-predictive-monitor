Out-of-the-Box Limitations
Relying strictly on the stock configuration presents a few constraints on granular control:

	API Exposure Boundaries: The default firmware on the Uno Q handles user applications via Linkable Loadable Extensions (LLX). Because this mechanism relies on pre-compiled symbols, only a predetermined subset of Zephyr and underlying hardware APIs are exposed by default. Attempting to call an unexposed kernel primitive or low-level function directly will fail because the core does not contain it out of the box.
	
	Synchronous Execution Constraints: Sticking purely to standard historical Arduino sketch methods restricts execution to a single synchronous loop. This design makes it highly challenging to manage multi-threaded scheduling, precise timing, or parallel processing primitives natively.

Bypassing the Limits for Granular Control
The architecture provides multiple pathways to break past these abstractions and achieve low-level control over the STM32U5 MCU:
	
	Hybrid RTOS Integration: The core does not entirely isolate the underlying operating system. Native Zephyr kernel APIs can be integrated directly into a standard Arduino sketch, enabling the definition of static threads with dedicated stacks that run independently of the traditional super-loop.
	
	Custom Core Symbol Exporting: If a specific granular API or register-level access function is missing from the default environment, the entire open-source Arduino core can be rebuilt. The LLX configuration can be modified to explicitly export the necessary kernel symbols and low-level hardware abstractions required for the application.
	
	Pure Zephyr Target Deployment: For absolute control without any middle layers, the Arduino core can be bypassed entirely. The MCU side of the board can be treated as a standard hardware target, allowing the deployment of custom firmware built directly from the main Zephyr repository.
